# Design System Alignment Agent - Permissions

## Permission Model

This document defines what the Design System Alignment Agent can read, modify, and must never touch.

---

## READ PERMISSIONS

### ✅ Always Allowed to Read

#### Design Tokens & Metadata
```
design-tokens/
├── component-properties.json    # Component metadata from Figma
├── colors.json                  # Color token definitions
├── typography.json              # Typography token definitions
├── spacing.json                 # Spacing token definitions
└── *.json                       # Any other token files
```

#### Storybook Components
```
apps/storybook/
├── src/components/              # All component implementations
├── src/tokens/                  # Theme and token files
├── .storybook/                  # Storybook configuration
├── package.json                 # Dependencies
└── **/*.stories.tsx             # All story files
```

#### Documentation
```
docs/
├── *.md                         # All documentation files
├── migration-plan.md            # Project roadmap
└── storybook-*.md               # Storybook guides
```

#### Configuration Files (Read-Only)
```
.env.example                     # Environment template
package.json                     # Root dependencies
tsconfig.json                    # TypeScript config
.gitignore                       # Git ignore rules
README.md                        # Project README
```

#### Production Portal (Reference Only)
```
index.html                       # Live portal - READ ONLY
public/                          # Public assets - READ ONLY
extracted-components/            # Legacy components - READ ONLY
```

#### Agent Files
```
agents/
└── design-system-alignment-agent/
    ├── brain.md                 # This agent's brain
    ├── permissions.md           # This file
    ├── workflow.md              # Review workflow
    ├── *.md                     # All agent docs
    └── reports/                 # Generated reports
```

## WRITE PERMISSIONS

### ✅ Allowed to Modify (After Approval)

#### Storybook Components
```
apps/storybook/src/components/
├── Button/
│   ├── Button.tsx               # Component implementation
│   ├── Button.stories.tsx       # Storybook stories
│   └── README.md                # Component docs
└── [Component]/
    └── ...                      # Same structure
```

**Conditions**:
- Only after explicit human approval
- Only for specific, identified issues
- Must generate diff preview first
- Must reference source of truth (Figma/tokens)

#### Storybook Documentation
```
apps/storybook/src/components/**/README.md
apps/storybook/src/**/*.mdx
```

**Conditions**:
- Only after approval
- Must improve clarity or accuracy
- Must not remove existing information

#### Agent Reports
```
agents/design-system-alignment-agent/reports/
└── *.md                         # Generated review reports
```

**Conditions**:
- Always allowed (this is the agent's output)
- Must follow report-template.md format
- Must include timestamp and version

## MODIFY WITH EXTREME CAUTION

### ⚠️ Requires Explicit Approval + Review

#### Package Dependencies
```
apps/storybook/package.json      # Storybook dependencies
package.json                     # Root dependencies
```

**Conditions**:
- Only when absolutely necessary
- Must explain why dependency is needed
- Must check for version conflicts
- Must not introduce security vulnerabilities

#### Storybook Configuration
```
apps/storybook/.storybook/
├── main.ts                      # Storybook config
├── preview.tsx                  # Global decorators
└── manager.ts                   # Manager config
```

**Conditions**:
- Only for critical fixes
- Must not break existing functionality
- Must test locally before suggesting

#### TypeScript Configuration
```
apps/storybook/tsconfig.json
tsconfig.json
```

**Conditions**:
- Only for type errors that block builds
- Must maintain strict mode
- Must not weaken type safety

## ABSOLUTE PROHIBITIONS

### 🚫 NEVER MODIFY

#### Production Portal
```
index.html                       # PROTECTED - Live production site
```

**Exception**: Only if explicitly instructed by human with clear reason.

#### Generated Token Files
```
design-tokens/
└── *.json                       # PROTECTED - Generated from Figma sync
```

**Reason**: These are generated by `sync-figma-tokens.cjs`. Manual edits will be overwritten.

#### Secrets & Environment
```
.env                             # PROTECTED - Contains Figma token
.env.local                       # PROTECTED - Local secrets
```

**Reason**: Security. Never read, log, or modify secrets.

#### Deployment Workflows
```
.github/workflows/
├── deploy.yml                   # PROTECTED - Portal deployment
├── deploy-storybook-vercel.yml  # PROTECTED - Storybook deployment
└── *.yml                        # PROTECTED - All workflows
```

**Exception**: Only if explicitly approved for workflow improvements.

#### Git Configuration
```
.git/                            # PROTECTED - Git internals
.gitignore                       # PROTECTED - Git ignore rules
```

**Reason**: Agent must not push, commit, or modify git directly.

## GIT & DEPLOYMENT RESTRICTIONS

### 🚫 Git Operations - NEVER ALLOWED

The agent must **NEVER**:
- `git commit` - No direct commits
- `git push` - No pushing to remote
- `git merge` - No merging branches
- `git rebase` - No rebasing
- `git reset` - No resetting history
- `git checkout` - No switching branches
- `git branch` - No creating branches

**Why**: All git operations must be human-controlled to maintain code review process.

### 🚫 Deployment Operations - NEVER ALLOWED

The agent must **NEVER**:
- Trigger GitHub Actions workflows
- Deploy to Vercel
- Deploy to GitHub Pages
- Modify deployment configurations
- Change environment variables in deployment platforms

**Why**: Deployments affect production and must be human-controlled.

## APPROVAL WORKFLOW

### Level 1: Auto-Approved (Report Only)

- Reading any allowed files
- Generating reports
- Creating action lists
- Analyzing alignment

**No approval needed** - these are read-only operations.

### Level 2: Human Approval Required

- Modifying Storybook component code
- Modifying Storybook stories
- Modifying component documentation
- Adding new dependencies

**Process**:
1. Agent generates report with proposed changes
2. Human reviews report
3. Human explicitly approves: "Apply fixes for [Component]"
4. Agent applies approved changes
5. Agent generates summary of changes made

### Level 3: Explicit Instruction Required

- Modifying `index.html`
- Modifying deployment workflows
- Modifying package.json (root)
- Deleting files

**Process**:
1. Human must explicitly request: "Modify [file] to [specific change]"
2. Agent confirms understanding
3. Agent shows exact diff
4. Human confirms: "Yes, apply this change"
5. Agent applies change
6. Agent reports completion

---

## FILE DELETION POLICY

### 🚫 Never Delete Without Approval

The agent must **NEVER** delete:
- Any production files (`index.html`, `public/`, etc.)
- Any token files (`design-tokens/`)
- Any component files
- Any documentation
- Any configuration files

### ⚠️ May Suggest Deletion (Human Decides)

The agent may **suggest** deleting:
- Unused story files (if component is removed)
- Duplicate files
- Temporary test files
- Old report files (after archiving)

**Process**:
1. Agent identifies file as potentially deletable
2. Agent explains why deletion is suggested
3. Agent lists risks of deletion
4. Human decides and executes deletion manually

---

## ERROR HANDLING

### If Agent Attempts Prohibited Action

1. **Stop immediately**
2. **Log the attempt** (for debugging)
3. **Explain why action is prohibited**
4. **Suggest alternative approach**

Example:
```
❌ Cannot modify index.html (PROTECTED)

Reason: index.html is the live production portal.

Alternative: If you need to update the portal, please:
1. Review the proposed change
2. Test locally
3. Manually edit index.html
4. Deploy via GitHub Actions
```
